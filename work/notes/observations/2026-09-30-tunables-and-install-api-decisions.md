# Decisions made while building tunables-and-install-api (2026-09-30)

Recorded for the `tunables-and-install-api` done record. Code sites: `packages/serpcast/src/options.ts` (header), the module comments of `transport.ts`, `serpcast.ts`, `decoy.ts`, `install.ts`, `install-recipes.ts` and `install-api.ts`.

Reality check: the task file sat in `work/tasks/backlog/`, not `ready/` as the dispatch said, and the spec in `work/specs/tasked/`. The premises held: every value the task names was a hard-coded constant (`IDLE_POLL_MS` 5, `MAX_REQUEST_BODY_BYTES` 1 MiB, `MAX_PREFLIGHT_AGE_S` 7200, declarative `MAX_REDIRECTS` 20, decoy `TOP`/`MAX_RELEVANT`/`PREFIX` 5/1/5, endpoint `MAX_BODY_BYTES` 16 MiB, installer caps), `decoyGuard` was `string[]` only, and install/doctor code was reachable from the CLI alone. The task reverses decision 1 of `2026-09-29-decoy-prone-recipes-decisions.md` (no `{include, exclude}` form) by owner decision.

1. **A bad option is a `RangeError`, not a `SerpcastError`.** Message `serpcast: <option> must be ..., got <value>`, thrown where the option is given (`createTransport`, `createSerpcast`, `runDeclarativeRecipe`, `isDecoy`, the installers). `SerpcastError` kinds describe what happened to a search; a bad configuration is a caller bug, and the chain already rethrows non-`SerpcastError`s as bugs. Alternatives: a new `config` kind (a new concept in the error vocabulary for a non-search failure), or `recipe` (re-means it). Touches every option.
2. **Existing numeric options are validated too** (`timeoutMs`, `maxBodyBytes`, `cooldownMs`, `sessionIdleMs`, and `strict` must be a boolean), as the task says "every numeric option". A caller passing a negative, NaN or fractional value used to get undefined behaviour; now it throws. `timeoutMs`, byte sizes, counts and the decoy thresholds must be whole numbers (libcurl takes `long`s); `idlePollMs`, `maxPreflightAgeS`, `cooldownMs`, `sessionIdleMs` may be fractional.
3. **Zero is accepted only for `cooldownMs` (no cooldown, which is what 0 already did) and `maxRedirects` (follow none).** Refused elsewhere: `sessionIdleMs: 0`, `idlePollMs: 0` (a busy loop), `maxPreflightAgeS: 0` (`preflightCache: false` is the off switch), and `decoyRule.maxRelevant: 0` even though "only fully irrelevant pages are decoys" is a meaningful rule, because the task's rule is "zero only where it means off". Reversible by relaxing the check.
4. **Transport options are checked by `createSerpcast` even when a `transport` is injected** (they are then ignored, as before): fail loud rather than silently accept a typo'd value.
5. **Endpoint `maxBodyBytes` is per engine**, on `searchcast: {endpoint, maxBodyBytes}` beside the existing per-endpoint `timeoutMs`, not an instance option: the instance-level `maxBodyBytes` is the transport's, and reusing the name for a second limit would make it mean two things. Engines are not constructed, so a bad value is found at search time and is a `recipe` failure of that engine (the existing mapping for a misconfigured engine); the endpoint `timeoutMs` is now checked the same way (a bad one used to throw a raw error out of the search).
6. **`decoyGuard.exclude` wins over `include` and over `decoyProne`**; the array form is `{include: array}`. `decoyRule` sets only the three thresholds the task names; the stopword list, the 3-character term minimum and the never-judged floor (fewer than 2 terms or 3 results) stay fixed, since they are what stops the rule judging on too little evidence. `isDecoy` takes the same rule as an optional third argument, and `DEFAULT_DECOY_RULE` and the `DecoyRule`/`DecoyGuard` types are exported.
7. **`reuseConnections: false`** gives each request (the preflight included) a multi handle of its own, closed as soon as the request settles, so nothing is cached (no connection, no TLS session); `close()` then has nothing to do. **`keepSessions: false`** reuses the chain's existing "concurrent search gets its own session, closed after" path for every search.
8. **Not made configurable, on purpose:** strict impersonation (already has `strict`), checksum pins, archive validation and the explicit-download rule (security guarantees); the installers' idle timeout (60 s with no byte at all is a dead connection, even over Tor) and the downloader's redirect limit of 10 (safety); the 5 s default preflight age when a server sends no `access-control-max-age` (the Fetch standard's value, which Chrome uses: changing it would stop mimicking the browser; `maxPreflightAgeS` still caps it); the status maps (202/403/429 `blocked`, 404/410 `recipe`: recipe semantics, not tuning); the pinned target and header tables (they change together with the library). The installers' size caps stay internal constants that may only be LOWERED (`maxArchiveBytes`, `maxUnpackedBytes`); a raised or invalid value is a `RangeError` before any request.
9. **`serpcast/install` is a new file, `src/install-api.ts`** (the name `install.ts` is the libcurl installer), exported as `./install` with its own `.d.ts`. Besides the four functions the task names it exports what an embedder needs to use them: `healthy`, `formatReport`, `formatRecipeSets`, `recipesDir`, `InstallError`, `LIBCURL_IMPERSONATE`, `dataDir`, `ECHO_URL`, the types, and the caps renamed `MAX_LIBCURL_*` / `MAX_RECIPES_*` (the two installers' constants share names). The CLI keeps importing the modules directly (unchanged).
10. **The existing "only download path" test was edited**, as the task asks ("keep it meaningful by asserting the main entry does not reach `download.ts`"): its exact importer lists now include `install-api.ts`, and a new test walks the static imports from `index.ts` and asserts no install/download module is reached, plus one that imports `serpcast/install` by name. This is the one existing test not passing unchanged.
11. **Two small fixes on the paths the new caps use**, so a lowered cap reports itself: a gzip over `maxUnpackedBytes` said "the archive is not a readable .tar.gz", now "the archive unpacks to more than N bytes" (`tar.ts`); an endpoint answer over its cap was reported as "a body that is not JSON" (and the destroy error could surface uncaught), now `answer larger than N bytes`. Error kinds unchanged in both.
