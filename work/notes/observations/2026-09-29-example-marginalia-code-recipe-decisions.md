## Decisions

1. **HTTP 503 is detected by catching the `transport` error of `ctx.http.json` and matching `HTTP 503` in its message.** `ctx.http.json` maps 429 to `blocked` already but 503 to `transport`, and a code recipe cannot throw a `transport` error itself (only `blocked`/`recipeError`, or any throw, which becomes `recipe`). The task says to use `ctx.http.json`, and keeping it keeps the runner's mapping for every other status (500 stays `transport`, 404 `recipe`, 403 `blocked`, invalid JSON `recipe`). Alternative: `ctx.http.get` and map statuses in the recipe (clean for 503, but any other non-2xx could then only be `recipe` or `blocked`, not `transport`). The message match depends on `code.ts`'s wording (`<name>: HTTP <status> from <url>`); the test "HTTP 503 ... is blocked" fails if it changes. A cleaner fix is a serpcast feature (e.g. a per-call status map for `http.text`/`json`, or exposing the status on the error), which is a separate task if wanted. Touches: nothing outside the example.
2. **No `count` is sent when the caller gives no `maxResults`** (the API's own default applies); otherwise `count = clamp(floor(maxResults), 1, 100)`. Alternative: always send a default count (a new user-visible default). The chain still cuts to `maxResults` afterwards.
3. **Tolerant result mapping:** entries without a string `url` are skipped, an empty `title` falls back to the `url`, an empty `description` gives no `snippet`. Without this one odd entry would make the whole answer a `recipe` error through the output validation. Alternative: map verbatim and let validation fail. A response without a `results` array is still a `recipe` error, as the task says.
4. **The key is read from `MARGINALIA_API_KEY` at each search, not at load time**, and an empty value falls back to `public`. The key is URL-encoded into the path. Since the key is in the URL, it appears in serpcast's error messages (they name the URL); the README and the module comment say so.
5. **README placement:** the serpcast README is the repo root `README.md` (copied into the package on publish). Its relative link to `examples/` would be dead on npm, so `examples/` was added to `NON_SHIPPED_PREFIXES` in `scripts/copy-publish-assets.mjs` (with a test), so the published README links it on GitHub like `docs/` and `work/`. Touches: the publish script (one prefix).
6. **The test lives in `packages/serpcast/test/marginalia-example.test.ts`** and loads the example by path through `loadCodeRecipe`, over the fake transport of `test/engines.ts` (keyed by the hostname `api.marginalia.nu`). The example is not type-checked (it is plain `.mjs`, outside every tsconfig) but is prettier-checked.
7. **Spec wording:** the spec's out-of-scope line allows example recipes "only for engines that offer keyless access openly". Marginalia needs a key, but openly offers `public` with no signup; the owner decided (2026-09-29) this qualifies. If that line should say so, it is a spec edit for a human.
