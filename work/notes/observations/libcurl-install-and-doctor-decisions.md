# libcurl-install-and-doctor: in-scope decisions

2026-09-28, task `libcurl-install-and-doctor`. None of these meets the ADR bar on its own; recorded here so the reviewer can ratify or reverse them. The code-level ones are also stated in the module comments of `packages/serpcast/src/{install,download,doctor,cli}.ts`.

## Decisions

1. **Checksums: reused, not duplicated, and re-verified.** `install-libcurl` reads `LIBCURL_IMPERSONATE` (`src/libcurl.ts`), which already covers linux-x64, linux-arm64, darwin-x64, darwin-arm64 and win32-x64, so no platform was added. Provenance is recorded in that constant's JSDoc: on 2026-09-28 every pinned digest was compared again with the `digest` field of the GitHub release API for tag v2.1.1 (all match), the linux-x64 archive was downloaded and hashed (matches), and each archive's `library` entry was listed and confirmed to be a regular file (the `.so`/`.dylib` names next to it are symlinks). musl and FreeBSD are still not pinned; the README points those users at `SERPCAST_LIBCURL_PATH`.
2. **CI now installs with `serpcast install-libcurl`; `.github/scripts/fetch-libcurl.mjs` is deleted.** The acceptance says the install command is the only code that downloads the library, and the CI script was a second copy of download + verify + unpack. CI runs the built bin with `XDG_DATA_HOME=$RUNNER_TEMP/xdg` and exports the path it prints. Touches: decision 17 of `impersonated-transport-decisions.md` (the CI mechanism it describes is replaced; the gate is unchanged). Alternative: keep the script and treat "serpcast" as the published package only.
3. **The download uses Node's own `http`/`tls` with a hand-written CONNECT and SOCKS5 tunnel (`src/download.ts`).** libcurl-impersonate cannot download itself, Node's `fetch` has no SOCKS support, and shelling out to a system `curl` would add a dependency. It accepts the same proxy schemes as the transport (`http://`, `socks5://` with local DNS, `socks5h://` with DNS at the proxy, optional `user:password`), defaults the proxy port to 1080 like libcurl, and ignores proxy environment variables like the transport. It follows at most 10 redirects (GitHub redirects release downloads to a storage host) and never from https to http. Limits: archive 128 MiB, unpacked 512 MiB, 60 s without data. Alternatives: undici's `ProxyAgent` (a new dependency, no SOCKS), system `curl`.
4. **`installLibcurl` is not exported from the library**; only `cli.ts` imports `src/install.ts`, and only `install.ts` imports `src/download.ts` (a test asserts both). This keeps the "never a side effect" property structural. Alternative: export it so a caller (webveil) can install programmatically; it can run the bin instead, and exporting later is additive.
5. **New error class `InstallError`**, printed by the bin as `serpcast: <message>` with exit 1. An install failure is not a search failure, so it is NOT a `SerpcastError` kind (CONTEXT's kinds describe searches; reusing `transport` would re-mean it). Touches: the CLI's error output contract (README exit-code notes).
6. **Output contract: progress on stderr, the installed path alone on stdout**, so scripts (CI) can do `lib="$(serpcast install-libcurl)"`. stderr says what was downloaded from (and through which proxy, credentials stripped), the verified sha256 and where the library went.
7. **Existing file policy (new refusal):** an identical file is left alone (`already installed`, exit 0); a differing one is kept and the command fails naming `--force`; `--force` replaces it. Every write is a temp file in the data directory renamed into place, and nothing (not even the data directory) is created before the checksum and the archive contents are verified.
8. **The archive is unpacked in-process** (gunzip + a minimal tar reader that extracts only the pinned `library` regular file, with GNU long-name and pax `path` support), not with a system `tar`. Only the one file is written, as `libraryFileName()` (`libcurl-impersonate.so`/`.dylib`/`.dll`), mode 0644.
9. **`doctor` echo service: `https://tls.browserleaks.com/json`** (`ECHO_URL` in `src/doctor.ts`), the service the fingerprint finding measured against (tls.peet.ws timed out there). It prints `ja3`, `ja3n`, `ja4`, `http2` (Akamai string) and `http2 hash`. A user-visible default; alternative: tls.peet.ws, or a `--echo-url` flag (not added: one more knob, tests inject the URL through the function instead).
10. **`doctor --remote` is skipped when impersonation is not active** (reported as `echo error: skipped: impersonation is not active`): it would only send a non-browser fingerprint to a third party. Alternative: send it anyway to show the plain fingerprint.
11. **`doctor` output is `name: value` text, exit 0 when impersonation is active (and `--remote`, if asked, answered), else 1.** It reports the library path, which setting named it (`--libcurl`, `SERPCAST_LIBCURL_PATH`, `LIBCURL_PATH`, or the data directory), its `curl_version()`, the pinned release, and the strict check's own error message as `problem`. It uses the strict check first and falls back to a non-strict load only to read the version. A new `locateLibrary()` in `src/libcurl.ts` returns the path with its source; `resolveLibraryPath()` now delegates to it (same behaviour). Not exported from the index.
12. **Per-command options:** the bin now parses the union of options and rejects, as a usage error (exit 2), an option the command does not take (`install-libcurl --recipe`, `doctor --force`) or positional arguments for `install-libcurl`/`doctor`. `query` accepts exactly what it did before.
