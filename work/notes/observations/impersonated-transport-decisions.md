# impersonated-transport: in-scope decisions

2026-09-28, task `impersonated-transport`. None of these meets the ADR bar on its own; recorded here so the reviewer and the later tasks (`declarative-http-runner`, `engine-chain-and-state`, `code-recipes`, `libcurl-install-and-doctor`) can ratify or reverse them. The code-level ones are also stated in the module comments of `packages/serpcast/src/*.ts`.

## Decisions

1. **Direct koffi binding, no `impers`** (owner decision in the task's forward-note, option (a) of the finding). The library is loaded with `koffi.load(path, {deep: true})` on Linux and FreeBSD. koffi is a runtime dependency; `pnpm-workspace.yaml` sets `allowBuilds: koffi: false` because koffi ships prebuilt binaries as optional dependencies and its install script is not needed (verified: it loads without it). Touches: nothing else.
2. **Public API shape.** `createTransport({libcurlPath?, proxy?, strict?, timeoutMs?, caPath?, maxBodyBytes?})` returns `{check(), session(cookies?)}`; requests are only made through a session (`session.request(url, {kind, referer?, signal?, timeoutMs?})`), so there is no hidden shared cookie state (finding, point 4). `check()` loads and verifies the library without a network call, for `doctor`. The option is named `libcurlPath` to match the planned CLI flag `--libcurl`. Alternatives: a bare `request()` on the transport with an optional session argument. Touches: `engine-chain-and-state` (its "transport settings"), `code-recipes` (`ctx.http`), `libcurl-install-and-doctor`.
3. **"Transport session"** is the term for the cookie half of a CONTEXT Session (added to `CONTEXT.md`). CONTEXT says to avoid "cookie jar" for Session; the class that stores cookies is `CookieStore`, its JSON is `StoredCookie[]`. `engine-chain-and-state` already speaks of "a transport session whose cookies are persisted in the store", so this reuses its word.
4. **One HTTP exchange per request: redirects are not followed and statuses are not interpreted.** Each hop is its own request so cookies and the header table apply per hop (libcurl's FOLLOWLOCATION would skip our cookie store). The declarative runner follows redirects itself (its task already says "follow redirects") and maps statuses to error kinds. Touches: `declarative-http-runner`, `code-recipes`.
5. **GET only.** The finding did not measure POST header placement (`origin`, `content-type`), so no method option exists yet. Touches: `code-recipes` (a JSON API needing POST must wait for a measured table).
6. **New refusals, both `recipe` errors:** a page-initiated kind (`same-origin-navigation`, `fetch`, `script`) without a `referer` (Chrome always sends one there, so sending none would be an incoherent request), and a URL that is not http(s). CONTEXT lists "a wrong URL template" under `recipe`. Alternative: omit the referer silently (rejected: strict by default).
7. **Abort rejects with the signal's reason**, like `fetch`, not with a `SerpcastError` (a caller's cancellation is not a failure). Touches: `engine-chain-and-state`, which must not count an abort as an engine failure.
8. **The caller's proxy is the only egress policy.** `CURLOPT_PROXY` is always set (`""` when none, which disables libcurl's `http_proxy`/`HTTPS_PROXY`/`ALL_PROXY`) and `CURLOPT_NOPROXY` is `""` (so `NO_PROXY` cannot bypass a given proxy); both are tested. Only `http` and `https` are allowed (`CURLOPT_PROTOCOLS_STR`).
9. **`caPath` option** (`CURLOPT_CAINFO`), default the library's built-in CA path. Needed by the tests (local TLS server with a self-signed certificate in `test/fixtures/`) and by any host whose libcurl-impersonate build points at a CA path that does not exist there. No option disables verification.
10. **`maxBodyBytes`, default 16 MiB**, applied to the raw body and to each decoding step (no decompression bomb); over it is a `transport` error. A new user-visible default; alternative: unbounded.
11. **Default per-request timeout is `DEFAULT_TIMEOUT_MS` (15 s) from `serpcast-recipe`**, reused rather than a second constant. The runner passes the recipe's own `timeoutMs` per request.
12. **Non-strict with no library at all still fails with `impersonation`**: there is nothing to send with. Non-strict only lets a plain libcurl proceed, and `check()` reports `impersonating: false`.
13. **Cookies are Chrome-exact in placement** (finding, point 3): the transport owns them and puts `cookie` between `accept-language` and `priority` (last for `script`); libcurl's cookie engine is never used. RFC 6265 storage and matching, Chrome's send order, `__Secure-`/`__Host-` prefixes enforced. No public suffix list: a `Domain` attribute must equal the host or contain a dot. SameSite is not enforced because every request kind serpcast sends is same-site.
14. **The library is pinned in memory** (`dlopen` with `RTLD_NOLOAD | RTLD_NODELETE`, handle leaked on purpose). Measured: without it every process that made an HTTPS request died with SIGSEGV at exit, because BoringSSL's thread-local destructors run on the exiting libuv worker threads after koffi has unloaded the library.
15. **Platforms without `RTLD_DEEPBIND` (macOS, Windows)** load the library plainly; strict mode still passes there (it checks TLS impersonation), and HTTP/2 HEADERS parity is documented as not claimed (unmeasured). Alternative: refuse in strict mode on those platforms (rejected: it would make serpcast unusable there over a frame-priority detail nobody has measured).
16. **`LIBCURL_IMPERSONATE`** (in `src/libcurl.ts`) pins release 2.1.1 (the version the finding measured) with the sha256 of the linux-x64, linux-arm64, darwin-x64, darwin-arm64 and win32-x64 `libcurl-impersonate-*` archives and the library's path inside each. Checksums come from the GitHub release API `digest` field, cross-checked by downloading the linux-x64 archive. musl and FreeBSD archives are not listed yet. The installed file name in the data dir is `libcurl-impersonate.so` / `.dylib` / `.dll` (`libraryFileName()`). Touches: `libcurl-install-and-doctor`, which must reuse these.
17. **Native tests in CI** (acceptance asks to record this). `.github/scripts/fetch-libcurl.mjs` (not in any published package) downloads the archive named by `LIBCURL_IMPERSONATE` for the runner's platform, verifies its sha256, unpacks it and CI exports `SERPCAST_LIBCURL_PATH`; the plain-libcurl strict-mode tests use the runner's `/usr/lib/x86_64-linux-gnu/libcurl.so.4` through `SERPCAST_TEST_PLAIN_LIBCURL`. Locally, without those variables, the verify gate skips them and prints why (a vitest `globalSetup`, because a message logged inside a skipped file is swallowed). The CI job now builds, fetches, then tests (the gate is unchanged: format, build, test). Alternative: a separate CI job only for native tests.
18. **One connection per request** (a fresh easy handle each time, so no connection reuse or TLS session resumption). Real Chrome would reuse the connection for a follow-up request to the same host. Alternative: one easy handle per session, serialized, reset between requests. Left for later if an engine is found to care.
19. **`sec-ch-ua` is computed** from `CHROME_MAJOR` with Chromium's brand GREASE algorithm rather than stored as a literal, so the target, the user-agent and the client hints all come from one constant. Tested against known Chrome 120, 124 and 146 values.
20. **The `impersonation` error message names `serpcast install-libcurl`**, which the `libcurl-install-and-doctor` task adds later (the task's spec asks for "install command, or set the path").
