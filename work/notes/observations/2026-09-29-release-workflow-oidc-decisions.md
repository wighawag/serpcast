# Decisions made while building release-workflow-oidc (2026-09-29)

Recorded for the `release-workflow-oidc` done record. None meets the ADR bar.

1. **Provenance is forced with `PNPM_CONFIG_PROVENANCE: true` in `release.yml`, not with `publishConfig.provenance`.** The task accepts "`publishConfig.provenance` or equivalent". The repo pins pnpm 11, which publishes natively instead of shelling out to the npm CLI; reading its bundled source (11.25.0) shows it takes `provenance` only from its config (`pnpm_config_*` env, CLI, rc files) and never reads `publishConfig.provenance` from package.json. Without the setting, pnpm 11 still auto-attests under OIDC for a public repo and package (as searchcast's pnpm 10 flow does), but it only warns and publishes unstamped if that fails. Setting it makes an unattested publish fail instead. Alternatives: `publishConfig.provenance: true` in each package.json (a no-op under pnpm 11, so it would claim something that does not happen), or relying on auto-detection like searchcast. Touches only the publish step of `release.yml`; the reason is also commented there.
2. **The `serpcast` package gets its README and LICENSE from webveil's `copy-publish-assets.mjs`, ported to `scripts/`.** The forward-note allowed either this or a stub package README pointing at the root one. I copied the script so the npm page shows the full root README, with links to `docs/`, `packages/`, `work/` and `CONTEXT.md` rewritten to GitHub URLs pinned to the `serpcast@<version>` tag that changesets pushes. It runs as the `serpcast` package's `prepack`, and the copies are gitignored in `packages/serpcast/.gitignore`. `serpcast-recipe` is not wired to it, because it has its own README and MIT LICENSE; a test checks this. The one change from webveil's copy is that `COPYRIGHT` was dropped from the list of files that do not ship, because this repo has no such file.
3. **No local `release` script, only `release:ci`.** searchcast also has a local `release` script (build, `git push`, publish). Publishing from a laptop would bypass the OIDC trusted publisher and the provenance requirement, so the only publish path is the workflow.
4. **The README status line no longer says "published at `0.0.0` as name placeholders"**, because the first changeset in this PR makes that false. The README also gains a short "Release" section.

Out of scope, noticed: `serpcast` depends on `serpcast-recipe` via `workspace:*`, which pnpm publishes as an exact version (`0.1.0`, not `^0.1.0`). So a user cannot pick up a `serpcast-recipe` patch until `serpcast` is released again. `workspace:^` would publish a caret range. This comes from the scaffold, so it is left as is.
